## 1. 最新需求：以本版为准

用户明确纠正：不需要训练计划；需要把身体疲劳程度或准备程度、运动能力相关指标数值化展示，展示趋势，并把运动相关客观参数的入口统一到锻炼页。

上一版“今日安排 / 周计划 / 训练建议”的规划方向已撤销。本版不包含课表、训练推荐、训练目标管理、计划完成率或生活任务。之前确认的“健康与规律运动，兼顾跑步进步”和“尽量自动、少询问”仍然适用。

定位：**身体与运动数据仪表盘**。回答“现在的状态怎样、与自己过去相比怎样、能力如何变化、所有参数在哪里看”。

核心显示规范：**数值 + 单位/尺度 + 可比变化 + 个人参照 + 趋势 + 来源与时效**。解释描述变化，不转成行动指令。

## 2. 页面结构

底部仍为“锻炼”。页内三个入口：**总览 / 趋势 / 全部参数**。

### 总览

1. 身体状态主卡：恢复准备度、评估时点、与上次可比评估的差值、近7次小趋势。
2. 状态构成：主睡眠、夜间 HRV、睡眠心率、近期运动量；显示真实单位和个人参照。
3. 运动能力：VO₂max、相似跑步的配速与平均心率；同时显示期间变化与小趋势。
4. 运动记录入口：最近一次记录、全部记录与手工补录。
5. 全部参数入口：分类查找所有运动及相关生理数据。

首屏以恢复准备度为主，下一层立即看到能力数值。原始参数有清晰入口，不把所有曲线堆在一页；也不把评分藏起来。

### 趋势

按“状态 / 能力 / 活动量”筛选，再选具体指标。默认 7 天 / 4 周 / 8 周；更长窗口属于后续读取与性能扩展，不能伪称当前训练模块已支持。

每张主图包含当前值、期内变化、横纵轴单位、个人历史参照、有效样本量、测量来源。点击一天或一次训练可查看原值与背景。需要对照时并列同步时间轴，不将不同单位画在没有明确标注的同一纵轴上。

### 全部参数

成为运动数据的统一入口：分组列表显示最新值、单位、日期和来源类型；点击进入同一套参数详情，查看历史、原始样本与计算口径。未接入的参数注明“未接入”，没有记录注明“暂无记录”，不是 0。

## 3. 身体状态：一个主指标，避免重复评分

### 3.1 恢复准备度（0–100，实验性估计）

主指标用于概括睡眠、夜间恢复信号和近期训练影响。值越高，仅表示本模型下恢复相关信号更有利；不表示剩余体力百分比、受伤概率或运动安全许可。

不再额外显示一个 `100 − 准备度` 的“疲劳分”，避免把同一信息伪装成两个独立指标。若未来引入独立疲劳估计，需先证明其输入、定义和验证与准备度有实际区别；本轮不新增该模型。

合成展示示例：

> 恢复准备度 68 / 100 · 实验  
> 较上次可比评估 −6 分  
> 过去28天个人常见范围 60–80 · 处于常见范围  
> 最近评估：今天 07:15 · 基于睡后数据  
> 下方展示近7次趋势与输入变化。

68 不再孤立出现。当前值、变化幅度、自己的历史分布一起解释数字。

### 3.2 评分方法与时间口径

当前代码已有恢复参考 v1。页面重规划不等于现有任意权重已获得科学验证；第一版可以复用可审查的 v1 计算，并继续明确标注实验性，不在 UI 任务中临时发明新权重或移植 Garmin 阈值。

为让趋势可比，建议主评分以**每日主睡眠结束时**作为统一评估锚点，界面表述为“最近一次睡后评估”。睡眠延迟入库后可重算该锚点。当天新运动单独体现在近期活动量/负荷中，不把睡后评估包装成实时全身疲劳。

现有 v1 按当前时刻计算，只有一个最新 `readiness`，尚无每日历史系列。采用睡后锚点属于待实现的口径变更，需要版本标识，不能无说明连接旧版日内分数。未来若增加日内准备度，必须与每日睡后趋势分开标注。

“个人常见范围”拟用此前最多28个有效、同算法版本、同评估口径点的 P25–P75；至少14个有效点才显示。该分位区间是产品统计约定，不是临床正常范围、置信区间或医学阈值。当前点不纳入自己的参照。

较上次变化仅在两个可比单点之间计算；如果并非昨天，明确写“较上次（日期）”，不能写“较昨日”。分数变化用“分”，不写百分比。

### 3.3 有限输入的数值显示

- 单点成立：显示数值及覆盖状态。
- 夜间证据充分，仅负荷缺失：按现有模型显示范围，例如 54–69；不取中点假装是一个精确分数，不显示精确的较上次差值。
- 核心证据不足或过期：显示“本次未评估”，保留上次有效结果的日期；睡眠、HRV、心率等可用原值仍然显示。
- 数据不齐不填 0，不显示“疲劳为0/准备度100”。

### 3.4 支撑状态的参数

- 主睡眠时长：小时/分钟；与个人近期中位数比较；不与全天含午睡的总睡眠混用。
- 夜间 HRV（SDNN）：ms；与同来源夜间基线比较；与全天 HRV 单独命名。
- 睡眠心率：bpm；同来源基线、绝对差值；不能与 Apple 静息心率混成同一条趋势。
- 近期运动量：近7天已记录时长、距离、次数，相对此前可比期间的变化。
- 心率负荷：已有实验 `bpm·min` 可在详情展示，带覆盖与缺失次数；它不是身体疲劳或肌骨负荷的直接测量。

“近期运动量”可以易懂地量化为“近7天跑步 240 分钟，比此前4个完整7天窗口的均值多 9%”。只比较同类运动和可比记录口径，不把跑步与力量时长直接换成同等生理负担，也不把有漏记的统计称为完整实际运动量。

## 4. 运动能力：先显示已有依据的真实量纲

### 4.1 心肺能力：VO₂max

显示 `ml/kg/min`、最近测量日期、同来源近4周/8周变化及曲线，明确“设备估计”。同来源、不同设备/算法变更要标记；没有证据时不按年龄/性别给排名，不把体重变化带来的相对值变化全部解释为体能变化。

### 4.2 跑步表现：配速与心率联合展示

初版复用现有同来源、相似距离比较，把数值成对放在一起：

- 近期配速 7′28″/km，之前 7′31″/km，快 3 秒/km。
- 对应平均心率 134 bpm，之前 138 bpm，低 4 bpm。
- 同距离组、前后样本数、时间段与未控制条件同时可查。

它回答“相似跑步表现有没有变化”，不能直接叫“同等心率配速”或“跑步效率提高百分之几”：现有分组只控制来源与距离，没有控制心率、路线、温度和运动目的。

距离、时长、历史最好成绩属于已观测运动表现，可以查看；不把最大历史距离等同个人耐力上限。

### 4.3 后续候选，不假装已支持

固定心率下的配速、配速稳定性、心率漂移、跑步经济性、跑力分与预测成绩，只有完成所需输入和方法核验后再加入。当前没有足够的分段配速、路线条件或专门能力模型，第一版不凭空补出分数。

跑后1/2分钟心率下降作为恢复反应参数，保留单位和采样条件；不直接将其命名为确定的心肺能力评分。

### 入口迁移规则

- “更多 → 运动记录”迁入“锻炼 → 全部参数 / 运动记录”，保留原有补录与查看能力。
- “趋势”中的运动、步数、距离、活动能量等数据入口归入锻炼的统一参数详情；如全局趋势保留摘要，点击统一跳转锻炼中的同一详情。
- 心率、睡眠和体成分属于跨领域数据，可在全局摘要中引用；锻炼内必须可以完整进入，不维护第二份数据或第二套计算口径。
- VO₂max、HRV、睡眠心率、负荷等已有锻炼详情整理为同一套参数路由。
- 营养、用药、同步设置等保留原功能归属；同步/数据质量可以从参数的来源信息链接进入。
- 同一指标保持唯一ID、单位、聚合规则和详情组件。入口整合不复制数据、不重建独立历史。

## 6. 趋势必须可比较

1. 准备度每天统一睡后锚点；当前值的时间和分数版本可见。原始心率可用日内时间轴，VO₂max按实际测量点，运动表现按训练事件，不强行全部变成每日均值。
2. 7天/4周/8周切换时改变展示窗口，不能偷偷改变该历史点的算法、基线或取样口径。
3. 准备度固定0–100轴；其它折线明确标单位和范围。柱状活动量以0为基线，缺测保留空缺。
4. 点估计、范围和缺失分开绘制。范围用区间标记，不连成伪精确折线；缺测不插值为恢复改善。
5. 个人参照只使用该点之前的记录，来源改变或算法升级需断开/标记，不用未来数据给过去建立基线。
6. 历史重算与当时已保存的观测分开标记。延迟入库可以修正历史，但保留更新时间与版本，不冒充过去当时已知结果。
7. 若展示56天准备度，需要向前读取“展示窗口 + 最长基线窗口 + 睡眠跨日缓冲”；现有仅56天输入不足以保证最早历史点有完整基线。
8. 分数用分、心率用bpm差、配速用秒/km差；百分比只用于具有明确分母的可比统计，分母为0或缺失则不计算。
9. 多指标对照使用同时间轴的分图或明确单位的并列图；不把尺度相差悬殊的数值叠成一条图形。
10. 个人范围表示“与自己过去相比”，不等于健康正常范围；不把心率、体重等默认着色为越低越好。

## 7. 自动化与解释的边界

新健康数据入库后自动更新原值、可计算指标与趋势，不需要日常打卡。缺少输入时说明缺什么；只在来源/口径矛盾需要用户选择时询问。

解释统一为“数值变化 + 关联数据 + 仍未知的部分”。例如“准备度较上次低6分；本次主睡眠记录更短”，不扩展为跑多久、做什么训练或下次安排。

AI可以可选地解释图表和指标含义，不负责生成基础数值、编造测量或给训练计划。离线能够完整显示数值、趋势与来源；不新增默认健康数据外发。
