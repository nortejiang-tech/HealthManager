实现 Foundation-only 的 demand/claim/outcome 值和纯 reducer，表达类型代次、同intent去重、ready/deferred/worker token、按类型公平轮转。暂不接入真实同步。

冻结接口与语义：

- `SyncReason: Int, CaseIterable, Sendable, Equatable` 至少含 `.observer`、`.foreground`、`.background`、`.manual`、`.retry`，用于 reducer 内按类型累积 reason bit mask。
- `SyncDemand: Sendable, Equatable` 精确包含 `types: Set<String>`、`reason: SyncReason`、`intentID: UUID`。
- `SyncClaim: Sendable, Equatable` 精确包含 `token: UUID`、`capturedGeneration: [String: Int64]`。
- `SyncSchedulingError: Error, Equatable` 至少含 `.emptyDemand`、`.generationOverflow(type: String)`、`.tokenMismatch(expected: UUID, actual: UUID)`；可以为伪造/越界 claim 增加明确 case。
- `SyncSchedulingState: Equatable` 提供 `init(requestedGeneration: [String:Int64] = [:], completedGeneration: [String:Int64] = [:])`，只读公开 `requestedGeneration`、`completedGeneration`、`activeToken`、`deferredTypes`，计算 `pendingTypes`、`readyTypes`、`isRunning`。
- `@discardableResult mutating func submit(_ demand: SyncDemand) throws -> Bool`：空类型报错；同 intent 全局幂等并返回 false；对所有类型先做溢出预检再原子递增，不能部分写入；一个类型无论收到多少事件仍只在 pending set 出现一次。
- `mutating func claimNext(token: UUID) -> SyncClaim?`：已有 active token 或无 ready 类型时返回 nil 且不改变 busy；每次只 claim 一个类型，capturedGeneration 固定 claim 时的 requested 值；按类型字典序循环游标公平选择，刚完成/释放的繁忙类型不能在另一个 ready 类型前连续霸占。
- `mutating func complete(_ claim: SyncClaim) throws`：只有 active token 匹配才能完成，仅把 captured 类型推进到 captured generation；若该类型期间收到更高代次仍保持 pending。伪造 generation 不得令 completed 大于 requested。
- `mutating func release(_ claim: SyncClaim, deferring types: Set<String> = []) throws`：token 规则相同，不推进 completed；只允许 defer 此 claim 捕获的类型，释放后没有 ready 类型时 `claimNext` 返回 nil 且 `isRunning=false`。
- `mutating func resume(_ types: Set<String>)` 只移除对应 deferred 标记。不得引入 `Task`、数据库、HealthKit、MainActor、计时器、静态可变状态或副作用。
