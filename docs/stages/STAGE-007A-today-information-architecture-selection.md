# STAGE-007A：今日信息架构原型选择

> 状态：ACCEPTED（方案 1；2026-07-14）
>
> 执行者：主架构师 + 用户；本阶段不交给 Coder

## 1. 本阶段只决定什么

在已经确认的「今日 / 饮食 / 用药 / 趋势 / 更多」五栏方向内，选择“今日”页的首屏信息层级。三个原型都保留现有饮食、用药、趋势、来源、同步、设置、报告与诊断能力；来源、同步中心、设置和诊断只调整入口归属，不删除能力。

本次选择不是批准图中的所有文字、数字或未来功能。原型用于比较信息结构，最终产品只能显示现有数据合同能证明的事实；任何不存在的数据源、自动建议或完整度结论都必须删除或另立阶段验证。

## 2. 共同产品边界

- 服务个人、私密、可纠正的多源健康管理，不把产品改成纯减脂或健美记录器。
- “今日”只整合已存在的睡眠、活动、饮食、用药和数据质量事实；不新造综合健康分、自动目标或诊断。
- 未知与数据不足必须显式，不能把 nil 变成 0、100% 或正常状态。
- 所有可行动入口必须进入现有真实流程，例如餐食手工记录/复用、用药记录、同步明细或数据依据。
- 不加入社区、排行、挑战、电商、广告、内容流、课程或竞品商业闭环。
- 不为原型接入云端、分析 SDK、食品库、OCR、条码或新 AI 动作。

## 3. 三个可选方向

### 方案 1：按时间展开的健康证据线

原型：`/Users/nortepro/.codex/generated_images/019f5b92-8926-7d51-af2d-50fac3a30f9f/exec-fb6ed132-cfec-404c-9f9b-9808108439f4.png`

- 层级：睡眠、用药、活动、餐食按一天时间顺序出现；缺失餐次与数据不足也进入同一证据线。
- 优点：跨域事实关系直观，来源提示与记录动作在同一上下文，最少依赖“系统替用户判断优先级”。
- 风险：项目多时首屏较长；若每类都展开，会重新制造信息拥挤。
- 实现约束：默认只保留一行摘要与必要状态，详情进入既有页面；不得把时间线包装成因果关系。

### 方案 2：先处理一个明确缺口，再看今日摘要

原型：`/Users/nortepro/.codex/generated_images/019f5b92-8926-7d51-af2d-50fac3a30f9f/exec-f0a0cac3-8d7e-4c12-959c-a59a11a764e5.png`

- 层级：首屏只放一个当前可完成的缺口，例如“午餐尚未记录”，下面是睡眠、活动、摄入和用药摘要。
- 优点：记录路径最短，能直接利用 STAGE-005 的最近餐复用能力，认知负担最低。
- 风险：需要可解释且稳定的优先级规则；不能让饮食长期压过用药、同步异常等更重要事项。
- 实现约束：v0.3 只允许从明确缺失事实中选择，不使用 LLM、健康评分或自动教练；用户必须能忽略动作继续看完整摘要。

### 方案 3：数据完整性优先的可信快照

原型：`/Users/nortepro/.codex/generated_images/019f5b92-8926-7d51-af2d-50fac3a30f9f/exec-14db78c4-6133-43bb-a5d6-bf1015972c5d.png`

- 层级：先说明哪些来源已更新、哪些待确认，再展示今日睡眠、活动、摄入、用药和热量缺口快照。
- 优点：最突出 HealthManager 的来源归因与对账优势，避免用户把未知数据当成健康异常。
- 风险：日常记录动作被数据运维状态压到次级；对没有同步问题的普通一天可能过重。
- 原型纠正：图中的“食物数据库 / 本地可用”不是当前能力，选择本方向也不得实现或展示；应替换为已有的 Apple 健康、手工记录、设备来源与同步状态。

### 原型资产边界

三张图片是当前 Mac 上的 Codex 生成资产，不在 Git 工作区内，因此不随本分支 push。上面的文字描述与产品边界才是可跨机器复核的合同；图片只用于当前机器上的用户选择。若改由另一台机器或另一位用户做视觉选择，必须先重新导出/附上原图，不得仅凭文件路径假设其可见，也不得根据文字自行重画后冒充原方案。
