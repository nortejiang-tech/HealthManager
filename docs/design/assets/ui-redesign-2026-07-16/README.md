# HealthManager UI 改版视觉参考索引

> 生成与筛选日期：2026-07-16
>
> 参考画布：iPhone 竖屏；多数文件为 853 × 1844，`13-summary-structure-only.png` 为 852 × 1846。

## 使用顺序

实现时必须按以下优先级处理冲突：

1. 真实代码与既有数据合同；
2. `docs/design/2026-07-16-ui-redesign-design-contract.md`；
3. ADR-002；
4. 本目录图片。

图片不是像素级需求，也不是可直接复用的品牌资产。图片中的示例数字、来源、授权、缺失状态和 AI 文案只有在真实数据支持时才能显示。

## 参考图清单

| 文件 | 页面 / 状态 | 使用边界 |
|---|---|---|
| `01-today-master-structure-only.png` | Today 主视觉 | 只参考层级、基线曲线与局部决策透镜。不得照抄“午餐尚未记录”、自动试算或任何缺餐推断。 |
| `02-diet-main-structure-only.png` | 饮食主页面 | 只参考日期、证据线、汇总和动作层级。不得生成“晚餐尚无记录”等固定餐次占位。 |
| `03-medication-main.png` | 用药主页面 | 参考计划、实际动作、下一计划和日志层级；计划时间不得冒充动作时间。 |
| `04-trends-main.png` | 趋势主页面 | 参考一张主叙事图 + 安静详情列表；不得生成健康评分或目标环。 |
| `05-more-main.png` | 更多 | 参考可信度路径与功能分组；不把“正常”当作无条件健康结论。 |
| `06-meal-editor.png` | 餐食编辑器 | 参考照片、描述、AI 估算、可编辑分项与保存层级；AI 结果始终为估算。 |
| `07-medication-plan-editor.png` | 用药计划编辑 | 参考计划、提醒与保存结构；通知未授权必须显式且不阻断无提醒保存。 |
| `08-metric-detail-sleep.png` | 通用指标详情模板 | 参考周期、比较基准、选中点、统计和来源层级；不同指标不得套用不适用的统计。 |
| `09-data-quality.png` | 数据质量 | 采用修正版“证据轨道”，不使用“良好 / 一致”健康结论。 |
| `10-sync-center-success.png` | 同步中心成功 / 空闲 | 参考真实状态机；“等待外部 App”是用户操作阶段，不是失败。 |
| `11-data-sources.png` | 数据来源 | 参考样本贡献和活跃日期。图中的品牌图标不是实现资产。 |
| `12-alerts.png` | 告警 | “标为已知”只改变告警可见状态，不修复数据。 |
| `13-summary-structure-only.png` | 日报 / 周报 | 只参考本地确定性摘要与可选 AI 评注的分层。图中“适中 / 与基线一致”等示例 AI 判断不得照抄。 |
| `14-workouts.png` | 运动记录 | Apple 健康实测与手工估算必须分开；来源、样本和估算方法可展开。 |
| `15-manual-activity-entry.png` | 补录活动 | 参考 `MET × 体重 × 时长` 公式与 75 kg 兜底说明；保存后不因未来体重变化自动重写。 |
| `16-meal-reuse.png` | 复用餐次 | 参考整餐复用和选择菜品两条路径；复用创建新草稿，不修改原记录。 |
| `17-dashboard-card-editor.png` | 编辑趋势卡片 | 拖动、隐藏、恢复应无需教程；隐藏不删除数据，恢复默认不是危险动作。 |
| `18-settings-data-ledger.png` | 设置 | 顶部“数据去向总账”是正式方向；默认本地，外部 AI 只在启用 / 主动触发时发送必要内容。 |
| `19-ai-config.png` | AI 功能设置 | 文本评注和照片分析是两个独立通道；AI 相关启用态使用紫色语义，不使用青绿冒充本地事实。 |
| `20-onboarding.png` | 首次 Apple 健康授权 | 明确读取与按需写回；此步骤不调用外部 AI。 |
| `21-health-unavailable.png` | Apple 健康不可用 | 对应 HealthKit 不可用，不写成“用户拒绝权限”；本地数据不被清除。 |
| `22-meal-item-evidence.png` | 餐食分项依据展开 | 人工修订不把估算变成已验证事实；保留模型、置信、准备状态和未知字段。 |
| `23-add-ai-provider-structure-only.png` | 添加兼容接口 | 只参考字段和隐私说明。普通“添加”按钮使用紫色或钴蓝，不使用警告橙。 |
| `24-activity-detail-corrected.png` | 活动详情 | 这是唯一有效的活动能量公式参考：`基础 + 活动 = 总消耗`，再减去`已知摄入 + 未知`，证据不足则停止。 |
| `25-apple-health-permission-scope.png` | Apple 健康权限范围 | 读取状态来自最近一次查询；没有样本不等于没有授权。 |
| `26-sync-failure.png` | 同步失败 | 区分已完成、失败、未执行；重试不删除上次成功数据。 |
| `27-diet-empty.png` | 今日饮食空白 | 空白不是缺餐结论；允许新增或复用真实历史记录。 |
| `28-today-loading.png` | Today 加载 | 中性骨架，不提前显示值、来源或状态；只说明正在读取本机数据库。 |
| `29-ai-partial-failure.png` | AI 部分失败 | 成功输入保留，失败输入可单独重试，用户可继续手工填写和保存。 |

## 明确排除

以下稿件未复制进本目录，也不得作为实现参考：

- 第一版数据质量故障面板：过度像运维告警台，并使用了没有证据的“良好 / 一致”判断；
- 第一版活动详情：错误地在饮食摄入前显示加号；
- 所有“健康天气”方向；
- 把编织隐喻当作页面主结构的方向；
- 过度简化、只有普通系统列表且没有证据层级的方向。
