# ADR-007: 独立保存个人固定菜品模板

## Status

Accepted

## Context

- 饮食编辑器已有拍照与文字 AI 识别、分项营养编辑和来源标记。
- 「我的常吃」已有按记录统计的食物候选、已匹配食物和个人配方；它没有保存一组饮食分项作为独立模板的模型。
- 个人配方由官方食材快照与确定性计算器计算，不能直接承载 AI 估算出的餐食分项事实。
- 备份目前为 formatVersion 3，用户创作数据按 JSONL 表备份，新增表需要推进备份版本。

## Decision

1. 新增独立的个人固定菜品模板表，模板保存名称和有序分项 JSON 快照。
2. 每个分项保存名称、克数、营养快照、加工状态、来源类型/引用/版本、置信度和用户修订标记；未知值保持 null。
3. 模板可以从常吃页新建/编辑，也可以由高频记录建议打开同一编辑器；最终由用户确认后保存。
4. 餐次编辑器增加多选器，可加入已匹配常吃食物、个人配方和固定菜品模板。最终餐次仍只由原有 MealPersistenceCoordinator 保存。
5. 模板不保存照片、餐次时间、备注、父级汇总或 HealthKit 标识；照片只用于当次 AI 识别。
6. 新增迁移 v15，并将备份格式升级为 v4，按字段只增不改规则导出和恢复模板。
7. 高频建议沿用现有餐次去重统计；当前统计窗口内记录至少 2 餐且尚无同名固定模板时显示“固定为菜品”建议。

## Rationale

个人配方表示“官方原料 + 配方克数 + 确定性营养计算”，而固定菜品表示“用户确认过的一组饮食记录分项”。将它们分开可以保留 AI/手工/官方来源语义，避免把用户日志重解释为官方配方。固定菜品版本不回写历史餐次，备份通过独立表延续已有个人创作数据的恢复路径。

## Consequences

- 数据库只新增表，不修改既有迁移或餐次/HealthKit 同步合同。
- 新旧 App 对 v4 备份的兼容遵循现有规则：新 App 可导入旧版本，旧 App 会拒绝更高版本。
- 模板营养事实仅反映保存时的编辑器快照；官方、AI 估算和手工来源继续按来源标记展示。
- 迁移、备份导入导出和真实设备上的旧数据升级仍需单独运行验证；本次代码改动本身不等于真机验收。
