# ADR-004：离线官方营养目录、个人常吃与配方计算的数据合同

> 状态：Accepted
>
> 日期：2026-09-17
>
> 接受依据：用户 2026-09-17 确定的需求（导航改版、营养表、官方来源可查、常吃食物与个人配方）；方案文档见 `docs/planning/2026-09-17-营养表与体验迭代/`。

## 1. 背景

v0.5.1 中餐次分项只有 `manual / ai_estimate / nutrition_database / nutrition_label` 四种来源，且没有任何食物营养参考目录（ADR-002 时期明确“当时不做食品数据库”）。本轮用户要求：基础食材使用可靠官方来源并可查看出处；从本人历史整理常吃食物；以参考食材组合个人菜品并计算每 100 g 营养。原 ADR-002 的范围限制由此解除。

## 2. 决策

### 2.1 三类数据分开（延续方案 §7.1）

| 数据 | 性质 | 存储 |
|---|---|---|
| 官方目录条目 | 只读、可版本化的应用资源 | 随 App 打包的 JSON（`Resources/FoodCatalog/food_catalog_v1.json`），查询完全离线 |
| 个人映射与配方 | 用户数据，**必须备份** | GRDB 表（v9 迁移新增），随备份包 formatVersion 2 导出 |
| 已保存餐次分项 | 历史快照 | 延续 ADR-001：保存时冻结名称/重量/营养/出处，不随目录或配方更新而改变 |

目录条目身份 = 来源机构 + 数据集版本 + 原始食品编号（`mext-01088` 形式的稳定 id）。中文名/别名只用于搜索展示，不作唯一键，不构成“同名即同物”的自动匹配。

### 2.2 首版目录来源与边界

- 来源：日本文部科学省《日本食品标准成分表（八订）增补2023年》（含 2026-03-27 勘误），41 条经人工核对的条目；构建过程与 SHA-256 见 `docs/food-catalog/README.md`。
- 取值：原表 kcal / たんぱく質 / 脂質 / 炭水化物印刷列，**不做 4/4/9 重算**；`-`（未测定）、`Tr`（微量）、`(x)`（推定）分别保留，不都转 0。
- 无准确条目的中国食材（如干豆腐/千张）**不强行匹配**，留在个人配方层；品牌商品（即食鸡胸等）留给包装标签来源。
- 目录更新不重算历史；资源缺失或为空时明确报错，不把空资源当成功。

### 2.3 新增分项来源枚举 `recipe_calculation`

`meal_items.provenance_kind` CHECK 约束（v5 建立）新增 `'recipe_calculation'` 取值（v9 迁移重建表扩展约束，保留既有数据）：

- 语义：该分项的营养由**个人配方 × 官方食材条目**按可食重量计算得出，保存时冻结为快照。
- 与既有枚举互斥使用：官方单品匹配 → `nutrition_database`；包装标签 → `nutrition_label`；配方计算 → `recipe_calculation`。**不得把配方计算伪装成 `nutrition_database`**，也不得把多次 AI 估值的平均冠以官方来源。
- 语义色：`recipe_calculation` 走 comparison 语义（有来源的参考），与 `EvidenceTone.forProvenance` 集中映射一致（ADR-002）。
- 导出/恢复/显示/解码同步支持该值；旧版本 App 遇到含该值的备份按既有“未知格式版本拒绝导入”策略处理。

### 2.4 个人常吃与配方的模型合同

- **个人映射（personal_foods）**：候选名 → 目录条目/配方的确认关系；含置顶、忽略、默认份量。被忽略的候选不再在“我的常吃”重现。
- **配方（personal_recipes + personal_recipe_versions）**：配方必须有**不可变版本**——修改配方生成新版本，旧餐次继续引用旧版本快照；原料引用官方目录条目 id 与版本，目录资源包替换后旧配方仍可解释。
- **常吃统计**：按 `meal_records.eaten_at` 本地自然日统计；每食物每餐只计一次；分项与备注不重复计数；删除/编辑餐次后频次随之刷新，不持久化固定排行榜。
- **配方计算**：同状态食材贡献求和 ÷ 实际成品重量 × 100；生料/熟食条目不直接混用；缺任一原料营养素 → 成品该项未知；缺成品重量 → 允许存草稿但不显示每 100 g；重量 0/负/非有限不参与计算；未知用油不得按 0；已含油的熟食条目不重复加油。
- 复用既有保存链路：从目录/常吃/配方“加入饮食”只产生编辑器草稿，最终保存统一走 `MealStore` + `MealPersistenceCoordinator`（HealthKit 副作用不变）。

### 2.5 备份格式 v2

- `formatVersion` 升至 2：新增 `personal_foods.jsonl`、`personal_recipes.jsonl`、`personal_recipe_versions.jsonl`。
- 新 App 兼容导入 v1（缺新文件按空表处理）；旧 App（supported 1...1）遇 v2 按 ADR-003 既有策略明确拒绝，不静默丢数据。
- 恢复顺序：配方版本先于配方、配方先于个人映射（引用完整性）；`INSERT OR IGNORE` 幂等，可重复导入。
- 目录条目在恢复端找不到（如换了资源包）时：餐次快照照常显示，不丢餐、不变 0。

## 3. 不做的事

- 不内置全量全球食品库、不做远程食品服务/推荐引擎/条码扫描。
- 不自动把 614 条 AI 估算批量升级为官方值；不重估历史。
- 不在首轮推导维生素保留系数；配方估算明示为估算。
- 不为目录浏览写任何餐次数据；换 Tab 只读。

## 4. 影响

- v9 迁移：`meal_items` 重建（扩展 provenance CHECK）+ 新增三张个人表；已发布迁移 v1~v8 不动。
- `BackupManifest.currentFormatVersion = 2`，`supportedFormatVersions = 1...2`；导出表清单追加三张个人表。
- 新模块：`Core/FoodCatalog`（目录）、`Core/PersonalFood`（常吃/配方）、营养表 UI。
