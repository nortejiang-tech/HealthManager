# ADR-005：我的参考表、USDA 可信检索与配方原料快照

> 状态：Accepted
>
> 日期：2026-09-18
>
> 接受依据：用户 2026-09-18 确认的三项增量需求（参考食材删除/恢复、按名称从可信资料库检索添加、常吃菜生成可编辑推测配方）；方案文档 `docs/planning/2026-09-18-营养表增删与配方推测.md`。本文优先于 ADR-004 中「仅离线目录/空白新建配方」的范围限制。

## 1. 决策

### 1.1 三层分离的数据模型（v10 迁移）

| 层次 | 表 | 合同 |
|---|---|---|
| 官方食品身份 | `official_foods` | 身份 = provider + 官方 food ID；中文名/别名差异不产生重复身份 |
| 官方资料版本 | `official_food_versions` | **不可变**；计量基准、完整营养快照、出处、版本/发布信息（无官方版本号用抓取日期识别，不伪造）；更新产生新版本行 |
| 我的参考表成员 | `personal_reference_entries` | 移除是 `is_removed` 状态变化；成员持有**选用版本指针**；重新添加恢复成员、不产生副本；身份唯一 |

种子策略：离线目录 41 条在首次启动一次性初始化为 active 成员；标记（`personalCatalog.seeded.v10`）持久化并随备份 settings 导出——恢复后不重播，用户移除的默认条目不因重启/升级/恢复复活（D3）。

### 1.2 配方原料完整快照（RecipeIngredient.nutritionSnapshot）

v0.6 的原料只存 catalogEntryId+版本标签，目录/成员变化会破坏可计算性。v0.7 起原料内嵌**完整营养快照**（每 100g/100mL 数值与质量标记、provider、版本、出处、抓取时间），随配方版本（进而随备份 v3）持久化：

- 计算与「加入饮食」一律**快照优先**，当前目录仅作 v0.6 旧数据兜底；
- v0.7 首启一次性回填旧配方：只用可确认的原版本资料（版本标签一致），补不上保持待修复，不冒充（V1）；
- 修复 RecipeEditorView/MyFrequentPanel 的「解析失败即跳过」路径：待匹配/缺失原料按未知贡献传播，不得输出误导性完整总量（R3）。

### 1.3 USDA FoodData Central 适配器

- 首版仅 Foundation / SR Legacy / FNDDS（每 100 g 口径）；品牌标签类（每份口径）不进入检索结果、详情映射直接拒绝——**每份≠每100g**；
- 营养映射按来源 nutrient ID（1008 kcal / 1003 蛋白 / 1004 脂肪 / 1005 碳水 / 1079 纤维 / 1093 钠），不按字段顺序或中文标签；能量口径规则：优先官方 kcal（1008），缺失而官方 kJ（1062）存在时单位换算并标记 estimated + 记录规则；不以 4/4/9 重算、不相加；
- null → 未测定「—」，不存在 trace 语义混淆；缺失一个字段不妨碍其他字段展示；
- key 存 Keychain（与 LLM key 独立），不入备份/日志/仓库；错误区分未配置/401/429/超时/断网（S4）；
- 添加必须先取得完整详情并明确计量基准（搜索摘要不能冒充完整记录，S3）；以身份幂等去重。

### 1.4 配方推测

- 模型只做「原料组成与用量的建议」：只能引用给定候选池的官方条目 ID，编造 ID/非法数量/自称已称量一律拒绝（R3）；
- 营养值只能来自资料快照，由本地 `RecipeCalculator` 计算；模型建议用量状态最高为 estimated；
- 无官方候选的原料保留「待匹配原料」占位行，可选择/替换/删除，受影响营养按未知传播；
- 重新生成先保留当前草稿、新推测由用户显式应用（R4）；推测初稿的保存走既有配方版本机制（新版本、旧版本不动）。

### 1.5 备份格式 v3

- 导出新增 `official_foods` / `official_food_versions` / `personal_reference_entries`（含移除状态、显示名、别名、选用版本）；配方原料快照随 `personal_recipe_versions.ingredients_json` 自然导出；
- 恢复顺序：身份 → 版本 → 成员；`INSERT OR IGNORE` 幂等，重复恢复不产生重复条目；
- v2 及更早格式兼容导入（缺新文件按空表处理）；旧 App 遇 v3 明确拒绝。

## 2. 不做的事

- 不引入自建后端/代理；不把品牌标签数据标成官方实测；不做全库爬虫打包。
- 模型不输出营养值，不把推测写成历史事实或已称重；不自动升级历史配方到新资料版本（提示新版本、显式采用留待后续）。
- 不因新增分类（sweetsSnacks/other）阻断旧备份解码。

## 3. 影响

- v10 迁移（已发布 v1~v9 不动）；备份 formatVersion 2 → 3。
- 新模块：`Core/FoodCatalog/PersonalCatalogStore`、`FoodSearchService`、`Core/FoodCatalog/USDA/USDAFoodService`、`Core/LLM/RecipeSuggestionService`。
- UI：营养表参考段改成员驱动（＋/左滑移除/撤销/空态）、添加食材页、设置页食材资料库入口、配方编辑器推测模式。
