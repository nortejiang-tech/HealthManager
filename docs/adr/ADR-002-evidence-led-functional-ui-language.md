# ADR-002：采用“基线叙事 + 局部决策透镜”的证据型 UI 语言

## Status

Accepted — 2026-07-16

## Context

以下事实已经由现有代码、已发布产品边界和本轮用户反馈共同确认：

1. HealthManager 的一级导航已经稳定为“今日 / 饮食 / 用药 / 趋势 / 更多”，并且来源、同步、数据质量、告警、日报/周报、运动和设置均有真实可达页面。
2. 产品的核心差异不是综合健康评分或自动教练，而是本地优先、未知值显式、来源可追溯、估算可区分、数据质量可检查。
3. 用户明确拒绝了“健康天气”等玄化隐喻，也拒绝了仅为视觉效果存在的花哨表达；用户接受“决策透镜”的产品思路，但要求整体克制、功能优先、色彩略微丰富。
4. 用户认为只做系统列表与普通卡片过于简单，也认为把概念包装得过满会显得牵强；最终接受“有一处功能性亮点，其余界面保持安静”的平衡方向。
5. 当前应用默认把健康数据保存在本机，但配置外部 LLM 后，日报/周报会发送聚合摘要文本，用户主动使用餐食照片分析时会发送所选图片。因此 UI 不能使用“任何健康数据都不会上传”这类绝对文案。
6. Apple 不向第三方 App 提供完整的读取授权清单；没有样本不能直接推导为没有授权。当前 UI 只能根据最近一次真实查询、显式写入授权状态和已记录错误描述状态。

本轮已生成并审阅 29 张页面与状态参考，稳定副本见：

- `docs/design/assets/ui-redesign-2026-07-16/`
- `docs/design/2026-07-16-ui-redesign-design-contract.md`

## Decision

1. 全局采用“基线叙事 + 局部决策透镜”方向：页面先按时间、来源或任务顺序讲清事实；每个页面最多保留一个能帮助用户理解或决策的表达性结构。
2. 采用四个跨页面语义色角色：
   - 钴蓝：已观测比较、选中时点、周期基准；
   - 青绿：本机事实、Apple 健康查询成功、已确认或已保存；
   - 珊瑚橙：缺失、未完成、需要处理或记录动作；
   - 柔紫：AI 估算、手工估算、假设或可选外部能力。
3. 现有 `CardTheme` 继续表达“活动 / 心率 / 睡眠 / 体成分 / 饮食”等指标家族身份；它不得替代第 2 条的证据状态语义。指标颜色和证据状态同时出现时，状态语义优先。
4. 页面默认使用暖象牙底、系统中文字体、强标题层级、轻分隔线和同一表面的列表分组；不把每段内容都做成卡片，不在卡片内继续套卡片。
5. 视觉参考只决定层级、密度、节奏和交互方向。任何图中文字、数值、图标或状态一旦与书面合同或真实数据语义冲突，以书面合同和数据语义为准。
6. 未知数据保持未知，不把 `nil` 变成 `0`、正常、完整或已授权；没有餐次计划时不生成“漏记早餐 / 午餐 / 晚餐”；没有用药动作日志时不生成“漏服”。
7. AI、手工估算和用户修订始终保留估算身份。人工修订份量或名称不会把 AI 结果变成已验证数据库事实。
8. 本轮 UI 改版不增加社区、广告、电商、课程、自动目标、健康评分、诊断、因果推断、云同步、食品数据库、OCR 或条码能力。
9. 实现采用阶段化 Coder 流程。主会话负责每阶段任务书、提示词和验收；只有前一阶段 PASS 后才生成下一阶段的最终提示词。

## Rationale

这个方向比纯系统列表更有辨识度，但把创新限制在“帮助理解事实和下一步”的结构上；它也比大面积概念隐喻更适合健康数据产品，因为用户能直接看到来源、未知、估算和停止条件。

四个语义色与 HealthManager 现有领域模型天然对应：已知事实、比较、缺失和估算本来就是产品必须区分的四类状态。把颜色绑定到这些状态，比按页面随意换色更可复用，也能让用户跨页面建立稳定预期。

保留 `CardTheme` 可以避免为改版推翻现有图表与指标家族；新增语义层只解决跨域证据状态，减少无关重写。

## Consequences

1. 需要新增一层轻量设计 token 与共享组件，但不得形成与 `CardTheme` 竞争的第二套指标主题系统。
2. Today 主视觉参考、饮食主页面参考和日报/周报参考中有少量无法由当前合同证明的示例文案；实现必须按设计合同纠正，不能逐字照图。
3. 数据来源参考图中的第三方图标只是构图参考。实现只能使用系统图标、已有合法资源或真实可用的来源图标，不能提取生成图中的品牌图标作为资产。
4. 所有阶段都需要同时验收视觉和事实语义。页面“看起来像参考图”但出现缺餐推断、错误公式、错误上传声明或估算冒充事实时，阶段必须 FAIL。
5. 设计参考只覆盖 iPhone 竖屏浅色主视觉；实现仍必须支持深色模式、Dynamic Type、VoiceOver 和 Reduce Motion，并由最终阶段补齐验证证据。
